## O que vamos fazer e por quê

Os testes automáticos dizem que o código faz o que combinamos. Mas ninguém ainda **usou a aplicação de verdade**, e a IA ainda só foi chamada por um dublê. Esta etapa faz duas coisas:

1. **Validação manual.** Seguir os 14 passos do `quickstart.md`, na tela, com a chave real do Gemini, e anotar o que acontece.
2. **Rodada 7: as dívidas.** Ao longo das rodadas 3 a 6 fui anotando "dívidas": coisas que não quebravam nada, mas que incomodariam em produção. Antes de pensar em deploy, escolhi as cinco que mexem com produção ou segurança e fechei todas.

## Passo a passo

### 1. Monte o ambiente

O `backend/.env` não vai para o Git, então você cria a partir do exemplo e preenche. Para a validação com IA você precisa de uma chave da API do Gemini (se não tiver, pule os passos 9 e 11 do roteiro; o resto funciona).

```bash
docker compose up -d
cd backend
cp .env.example .env     # preencha GEMINI_API_KEY, JWT_SECRET, SEED_USUARIO e SEED_SENHA
npm ci
npx prisma migrate deploy
npm run seed             # cria o primeiro usuário a partir de SEED_USUARIO / SEED_SENHA
npm run dev              # API em http://localhost:3000
```

Em **outro terminal**:

```bash
cd frontend
npm ci
npm run dev              # app em http://localhost:5173
```

Os dois servidores de desenvolvimento não terminam. Se você juntar migração, seed e servidores num comando só, ele nunca volta (aconteceu comigo e estourou o tempo limite). Rode cada passo separado.

Um tropeço meu para você evitar: na pasta principal não havia `node_modules`, e o `npx prisma` baixou outra versão do Prisma (a 8, em testes), na qual o comando `migrate` nem existia. Rode `npm ci` nas duas pastas **antes** de qualquer `npx`.

### 2. Gere os arquivos de teste do passo 6

O passo 6 do roteiro usa três PDFs: um válido, um texto puro com extensão `.pdf` e um acima de 50 MB. Este script cria os três na pasta atual:

```javascript
import { writeFileSync, appendFileSync } from 'node:fs';

const pdf = (texto) => {
  const conteudo = `BT /F1 12 Tf 72 720 Td (${texto}) Tj ET`;
  return [
    '%PDF-1.4',
    '1 0 obj << /Type /Catalog /Pages 2 0 R >> endobj',
    '2 0 obj << /Type /Pages /Kids [3 0 R] /Count 1 >> endobj',
    '3 0 obj << /Type /Page /Parent 2 0 R /MediaBox [0 0 612 792] /Contents 4 0 R /Resources << /Font << /F1 5 0 R >> >> >> endobj',
    `4 0 obj << /Length ${conteudo.length} >> stream\n${conteudo}\nendstream endobj`,
    '5 0 obj << /Type /Font /Subtype /Type1 /BaseFont /Helvetica >> endobj',
    'trailer << /Root 1 0 R >>',
    '%%EOF',
    '',
  ].join('\n');
};

writeFileSync('1-contrato-valido.pdf', pdf('Contrato de compra e venda. Multa de 20 por cento por rescisao antecipada. Foro: Sao Paulo.'));
writeFileSync('2-falso-texto-renomeado.pdf', 'isto e texto puro, nao e um PDF\n');
writeFileSync('3-grande-demais-51MB.pdf', pdf('grande demais'));
appendFileSync('3-grande-demais-51MB.pdf', Buffer.alloc(51 * 1024 * 1024));
```

Salve como `gerar.mjs` e rode `node gerar.mjs`. O PDF válido é mínimo; se o seu navegador ou a IA reclamarem dele, use qualquer PDF pequeno de verdade.

O passo 14 é o mais bonito: é a regra da constituição ("apagar inclusive em caso de erro") conferida na prática, com a pasta de uploads **vazia** depois de um upload bem-sucedido, um recusado e uma análise.

No meu caso, os 14 passos passaram. O passo 3 eu não esperei os 15 minutos do desbloqueio, só conferi o aviso.

### 4. O passo 9 falhou de primeira, e a culpa não era minha

Na tela apareceu "serviço de análise temporariamente indisponível". Primeiro reflexo: achar que meu código tinha um bug. Antes de mexer em qualquer coisa, olhei o log do backend, que mostra o que o Google devolveu:

```text
503 UNAVAILABLE: This model is currently experiencing high demand.
Spikes in demand are usually temporary. Please try again later.
```

A chave estava certa (a chamada chegou ao Gemini), mas o **modelo estava sobrecarregado**. O app fez o certo: mapeou o erro para `503 IA_INDISPONIVEL` e mostrou a mensagem combinada, sem vazar nada técnico (Princípio III). Sem querer, isso foi um ensaio do passo 11. Mais tarde o Gemini voltou ao normal e a análise funcionou, sem mexer em código.

**Leia o log antes de "consertar".** A mensagem da tela é genérica de propósito; o motivo de verdade está no log do servidor.

### 5. O passo 11: o `.env` só é lido na partida

Para simular a chave inválida, trocar o `backend/.env` não bastou: o servidor leu o arquivo ao subir. O `tsx watch` vigia o código, não o `.env`. Foi preciso **reiniciar o backend**, e de novo para restaurar a chave depois:

```powershell
# Windows: parar o que escuta na porta 3000 e subir de novo
Get-NetTCPConnection -LocalPort 3000 -State Listen | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
```

```bash
cd backend && npm run dev
```

No macOS/Linux, basta `Ctrl+C` no terminal do backend e `npm run dev` outra vez.

### 6. A rodada 7: fechar as cinco dívidas

Essas cinco tarefas não estavam no `tasks.md` original. Eu criei uma "Fase 10: Dívidas técnicas antes do deploy" (T079 a T083), para a rodada ter escopo explícito, como manda o ADR de implementação. Divergir do plano está certo, desde que fique escrito.

| Tarefa | O problema | A correção |
|---|---|---|
| T079 | `rename` falha com `EXDEV` quando a pasta temporária e o storage ficam em volumes diferentes (comum em Docker) | se der `EXDEV`, copia e apaga o temporário |
| T080 | o download do PDF não dizia ao navegador para não guardar cache nem adivinhar o tipo | `Cache-Control: private, no-store` e `X-Content-Type-Options: nosniff` |
| T081 | **corrida no `PUT` do contrato**: a transação confirmava *antes* de o PDF novo entrar no storage; uma análise pedida nesse intervalo lia o PDF antigo e gravava como se fosse do novo | o `rename` do PDF passou para *dentro* da transação, antes do commit |
| T082 | `fotoUrl` aceitava texto de qualquer tamanho | máximo de 2048 caracteres, no backend e no formulário |
| T083 | o frontend era um arquivo só de 964 kB (o Vite avisava) | `React.lazy` nas telas e grupos de vendor |

Backend e frontend não se tocam, então rodaram em paralelo. A T081 foi sozinha: mexe em concorrência, e os testes do backend dividem o mesmo banco, então dois rodando juntos se atropelariam.

**A corrida do `PUT`, explicada.** Antes, a ordem era: (1) grava no banco e confirma; (2) move o PDF novo para o storage. Entre o 1 e o 2 existia um intervalo minúsculo em que o banco já dizia "contrato novo", mas o arquivo ainda era o velho. O teste que prova isso falhou primeiro, como deve: ele pausa o `PUT` exatamente no `rename` e dispara a análise nesse momento. Depois da correção, o `update` da linha segura um *lock* no Postgres, e a trava do `POST /analise` espera esse lock soltar.

Troquei um problema por outro menor: se o commit falhar *depois* do `rename`, fica o PDF novo com a linha antiga. Aceitei, por escrito, como Ruling.

**Resultado do bundle (T083):**

| | Antes | Depois |
|---|---|---|
| Arquivo JS | 1 de 964,61 kB | maior: `home` com 361,68 kB (gráfico) |
| Carregado de início | 964 kB | 542 kB |
| Aviso do Vite (>500 kB) | sim | sumiu |

### 7. A revisão achou um defeito na junção de duas tarefas

A revisão aprovou as cinco tarefas, sem nada Critical, mas achou um **Important** de verdade: o fallback do `EXDEV` (T079) copiava *por cima* do PDF do contrato. Se a cópia morresse no meio, o PDF ficava truncado, e no `PUT` o banco desfazia mas o arquivo antigo já tinha sido estragado. Cada tarefa estava certa sozinha; a costura entre a T079 e a T081 não.

A correção: copiar para `<destino>.<uuid>.part` na mesma pasta e só então fazer `rename`, que é atômico.

### 8. Quando o filtro de segurança do modelo corta o trabalho

Na T081, o filtro de segurança do modelo cortou **dois** implementadores no meio do trabalho (primeiro o Opus, depois o Sonnet), com "safeguards flagged this message". Era alarme falso: o texto falava só de concorrência e arquivos. O que fazer: **confira o repositório antes de repetir a tarefa.** O primeiro não tinha deixado nada; o segundo já tinha feito o commit e o relatório antes de ser cortado. Rodei a suíte eu mesmo (308 testes verdes) e segui para a revisão.

## Se o seu deu diferente

- **O passo 9 devolve "serviço indisponível".** Leia o log do backend antes de qualquer coisa. Se for 503 do Google, espere e repita. Se for 400 ou 403, a chave está errada ou sem permissão.
- **Você não tem chave do Gemini.** Pule os passos 9 e 11. O resto do roteiro vale.
- **O modelo do Gemini do plano (`gemini-3.8-flash`) não existe mais ou mudou.** Serviço externo muda. Troque pelo modelo equivalente atual, anote no seu diário e rode o passo 9 de novo.
- **A troca de chave no passo 11 não surtiu efeito.** Reinicie o backend. O `.env` só é lido na partida.
- **A sua lista de dívidas é outra.** Normal. Escolha as que mexem com produção ou segurança e deixe as outras anotadas. Anotada não é paga: eu deixei vários itens em aberto, de propósito (acessibilidade do menu de perfil e do gráfico, "tentar de novo" na Home, alguns testes menores). A lista completa está no fim da entrada 18 do diário do laboratório.
- **Os números de tamanho do bundle são diferentes.** Dependem das versões. O que vale é o aviso sumir e o carregamento inicial ficar abaixo dos 500 kB.

Para retomar do meu ponto: `git checkout fase-6-validacao` (depois da validação) ou `git checkout 4ae7ba1` (depois da rodada 7).

## O que isso mostrou

- **Mudou o `.env`? Reinicie o servidor.** Variáveis de ambiente são lidas só na partida.
- **Uma IA externa vai ficar indisponível de vez em quando.** Tratar isso com mensagem amigável não é capricho, é requisito.
- **Testar com a chave real mostra o que o dublê esconde.**
- **Consertar uma coisa pode abrir outra.** O fallback do `EXDEV` estava certo sozinho, mas junto com o `PUT` virou risco. Quem achou foi a revisão olhando as duas juntas.
- **Teste de corrida precisa de um gancho no ponto exato**, não de `sleep` e sorte.
- **Dividir o bundle traz uma falha nova:** se um pedaço não carregar (por exemplo depois de um deploy, com nome de arquivo antigo), a tela quebra. Eu ainda não tinha um `ErrorBoundary`. Eu devia ter planejado isso desde o início; virou dívida.
- **Divergir do plano é ok, se ficar escrito.**
